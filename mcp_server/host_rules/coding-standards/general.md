# General Coding Standards (언어 공통)

특정 언어 표준이 없거나, 모든 언어에 공통으로 적용되는 기본 원칙입니다. 언어별 문서(`coding-standards/{language}.md`)가 있으면 그쪽이 우선합니다.

## 1. 가독성 · 명명
- 이름은 의도를 드러내게(축약어 남용 금지). 불리언은 `is`/`has`/`should` 접두.
- 함수는 **한 가지 일만** 하고 짧게. 깊은 중첩보다 **early-return(guard clause)** 을 씁니다.
- 매직 넘버·문자열은 **상수화**합니다.

## 2. 단순성 · 중복
- **요청받은 것만 구현**합니다. 불필요한 추상화·가정용 기능(over-engineering) 금지.
- 중복은 **반복되면(예: 3회)** 추출합니다(성급한 DRY도 지양).
- 기존 코드·유틸을 재사용합니다. 있는 바퀴를 다시 만들지 않습니다.

## 3. 주석 · 문서
- 주석은 **"왜"** 를 적습니다("무엇"은 코드가 이미 말함).
- 죽은 코드·주석 처리된 코드를 남기지 않습니다(git이 기억함).
- `TODO`/`FIXME` 는 맥락(또는 이슈 키)과 함께 남깁니다.

## 4. 오류 처리
- 실패를 **조용히 삼키지 않습니다**(빈 catch 금지). 복구 불가면 컨텍스트를 담아 전파/로깅.
- 경계(사용자 입력·외부 API)에서 검증하고, 내부 계약은 신뢰합니다.
- 발생할 수 없는 상황에 대한 방어 코드로 과설계하지 않습니다.

## 5. 불변성 · 상태
- 가능하면 **불변(immutable)** 을 선호하고, 가변 전역 상태를 피합니다.
- 부수효과를 좁은 범위로 가둡니다.

## 6. 자원 · 로깅
- 파일·커넥션·락 등 자원은 확실히 해제합니다(`finally`/`with`/RAII).
- 사용자 대상 출력과 로깅을 구분하고, 로그에 비밀·PII를 남기지 않습니다(→ `security-guidelines.md`).

## 7. 보안 · 비밀
- 비밀(키/토큰)을 코드·로그·커밋에 남기지 않습니다(→ `security-guidelines.md`).
- 외부 입력은 신뢰 경계에서 검증합니다.
