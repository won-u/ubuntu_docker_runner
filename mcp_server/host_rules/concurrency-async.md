# Concurrency & Async (개인 동시성·비동기 기준)

> 동시성·병렬·비동기 실행에 언어무관으로 통용되는 기준이다. 언어별 문법·관용구는 `coding-standards/{language}.md` 를, 개인 특화 규칙은 이 문서에 추가한다.
> **원칙: 공유 가변 상태를 최소화한다. 동시성은 필요할 때만 도입하고, 안전성을 설계로 보장한다.**

## 1. 공유 상태 최소화
- 가장 안전한 동시성은 **공유하지 않는 것**이다. 불변 데이터·메시지 전달·작업 격리를 우선한다(→ `coding-standards/general.md`).
- 공유 가변 상태가 불가피하면 **접근 지점을 좁히고** 명시적으로 동기화한다.
- 전역 가변 상태를 여러 실행 흐름이 동시에 건드리게 두지 않는다.

## 2. 락 규율
- 락은 **짧게** 잡고, 락을 쥔 채 외부 호출·IO·긴 작업을 하지 않는다.
- **락 순서를 전역에서 일관**되게 정해 데드락을 막는다(항상 같은 순서로 획득).
- 중첩 락을 피한다. 가능하면 고수준 동시성 원시(큐·액터·불변 스냅샷)로 락을 대체한다.
- 락 자원도 확실히 해제한다(`finally`·`with`·RAII → `coding-standards/general.md`).

## 3. 원자성 · 가시성
- "읽고-수정하고-쓰기"는 원자적이지 않다 — 원자 연산·트랜잭션·락으로 보호한다.
- 한 스레드의 쓰기가 다른 스레드에 즉시 보인다고 가정하지 않는다(메모리 가시성). 언어의 메모리 모델·동기화 수단을 따른다.
- 검사-후-행동(check-then-act) 경쟁을 주의한다(→ `code-review-guidelines.md` race 체크).

## 4. 비동기 위생
- 이벤트 루프·단일 스레드 런타임에서는 **블로킹 작업으로 루프를 막지 않는다**(오프로딩한다).
- 시작한 비동기 작업을 방치(floating)하지 않는다 — 대기하거나 명시적으로 관리한다(→ `coding-standards/{language}.md`).
- 독립 작업은 병렬화하되 **동시성 상한**을 두어 자원 고갈·과부하를 막는다(→ `performance-guidelines.md`).

## 5. 취소 · 타임아웃
- 모든 대기(네트워크·락·큐)에 **타임아웃**을 둔다(→ `error-handling-resilience.md`).
- **취소를 전파**한다 — 상위가 취소되면 하위 작업·요청도 중단되게 컨텍스트·토큰을 넘긴다.
- 취소·타임아웃 시에도 자원을 정리하고 일관된 상태를 남긴다.

## 6. 계약 · 검증
- 함수·타입의 **스레드 안전 여부를 문서화**한다(안전·조건부·비안전).
- 동시성 코드는 결정론적으로 테스트하기 어렵다 — 경합 유발 테스트·스트레스·정적 분석을 병행한다(→ `testing-standards.md`).
- DB 동시성 충돌은 낙관적 락·격리수준으로 다룬다(→ `data-persistence.md`).
