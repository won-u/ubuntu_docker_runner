# Configuration Management (개인 설정·환경 관리 기준)

> 애플리케이션 설정과 실행 환경 관리에 일반적으로 통용되는 기준이다. 개인 특화 규칙(설정 스토어·시크릿 매니저 등)은 이 문서에 추가한다.
> **원칙: 설정은 코드에서 분리하고 환경별로 주입한다. 한 번 빌드한 산출물이 어디서나 돈다.**

## 1. 코드와 설정의 분리 (12-factor)
- 환경에 따라 달라지는 값(호스트·포트·URL·자격증명·토글)은 **코드에 하드코딩하지 않는다**. 환경변수나 설정 파일로 주입한다.
- 하나의 빌드 산출물이 dev/stg/prod 어디서나 동작해야 한다. 환경별로 코드를 분기하지 않는다.
- 설정을 읽는 지점을 **한 곳(config 모듈)**으로 모으고, 나머지 코드는 타입화된 설정 객체만 참조한다.

## 2. 시크릿과 일반 설정의 구분
- 비밀(키·토큰·비밀번호)은 일반 설정과 **다르게** 취급한다 — 저장소에 커밋하지 않고, 로그에 남기지 않는다(→ `security-guidelines.md`).
- 예시 파일(`.env.example`)에는 **키만** 두고 값은 비운다. 실제 값 파일은 gitignore 한다.
- 프로덕션 시크릿은 시크릿 매니저·CI 시크릿에 둔다. 개발용과 운영용을 섞지 않는다.

## 3. 검증 · 기본값 · 우선순위
- 설정은 **시작 시점에 검증**한다. 필수값 누락·타입 오류·범위 위반이면 즉시 fail-fast 로 죽인다(→ `error-handling-resilience.md`).
- 안전한 **기본값**을 제공하되, 프로덕션에서 위험한 기본값(디버그 on·인증 off)은 금지한다.
- 우선순위를 명확히 한다: 보통 CLI 인자 > 환경변수 > 설정 파일 > 기본값.

## 4. 환경별 설정
- 환경(dev/stg/prod)마다 달라지는 부분만 오버라이드하고, 공통은 한 번만 정의한다.
- 현재 환경을 명시적 변수(예: `APP_ENV`)로 두고, 알 수 없는 환경이면 죽는다.

## 5. 피처 플래그
- 미완성·실험 기능은 **플래그 뒤에** 둔다. 플래그는 기본 off, 켜는 조건을 명확히 한다.
- 수명이 끝난 플래그는 **제거**한다(죽은 분기·설정을 방치하지 않는다).
