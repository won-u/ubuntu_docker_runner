# Internationalization & Localization (개인 국제화·현지화 기준)

> 다국어·다지역 지원(i18n/l10n)에 일반적으로 통용되는 기준이다. 개인 특화 규칙(대상 언어·번역 워크플로 등)은 이 문서에 추가한다.
> **원칙: 텍스트·포맷·인코딩을 코드에서 분리한다. 사용자의 언어·지역·시간대는 런타임에 결정된다.**

## 1. 문자열 외부화
- 사용자 대상 문자열을 **코드에 하드코딩하지 않는다** — 리소스·메시지 카탈로그로 분리한다.
- 문장을 조각내 이어붙이지 않는다(어순이 언어마다 다르다). **플레이스홀더**가 있는 완전한 문장 단위로 번역한다.
- 복수형·성별 등 언어별 규칙(복수 카테고리)을 지원하는 포맷을 쓴다.

## 2. 인코딩
- 저장·전송·처리를 **UTF-8** 로 통일한다. 바이트 길이와 문자(그래핌) 길이를 혼동하지 않는다.
- 파일·DB·HTTP 헤더의 인코딩을 명시한다. 인코딩 추측에 의존하지 않는다.

## 3. 로캘 인식 포맷
- 날짜·시간·숫자·통화·정렬은 **로캘 규칙**에 따른다 — 포맷 문자열을 직접 짜맞추지 않는다.
- 로캘은 UI 언어와 **분리**될 수 있다(언어=한국어, 지역 포맷=미국 등). 각각을 다룬다.

## 4. 시간대
- **이미 일어난 시점**(로그·생성/수정 시각 등)은 **UTC 로 저장**하고, **표시할 때만** 사용자 시간대로 변환한다.
- **미래의 벽시계 약속**(회의·알람·청구일 등)은 UTC 로 굳히지 않는다 — 사용자가 정한 **로컬 시각 + IANA 시간대 ID**(예: `Asia/Seoul`)를 함께 저장하고 발화 시점에 해석한다. 시간대 규칙(DST 정책 등)은 tzdb 갱신으로 **바뀌며**, UTC 로 굳혀둔 미래 시각은 그때 사용자가 의도한 벽시계 시각에서 어긋난다.
- 시간대는 **ID로** 저장한다. 오프셋(`+09:00`)만 저장하지 않는다 — 오프셋은 특정 시점의 결과일 뿐 규칙을 담지 못한다. tzdb 는 최신으로 유지한다.
- 서버·DB·컨테이너의 시간대 가정을 코드에 박지 않는다(→ `configuration-management.md`).

## 5. 검증
- 최소 하나의 **비영어·비ASCII 로캘**로 실제 렌더링을 확인한다(레이아웃 깨짐·잘림·인코딩 오류).
- 텍스트 확장(번역이 길어짐)과 RTL 가능성을 레이아웃에서 고려한다.
