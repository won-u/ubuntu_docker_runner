# Diagram Guidelines (개인 다이어그램 규약)

> 아키텍처·설계 다이어그램에 일반적으로 통용되는 기준이다. 개인 특화 규칙은 여기에 추가한다.
> **원칙: 다이어그램은 소스(텍스트)로 버전 관리하고, 하나의 추상화 레벨을 유지한다.**

## 1. Diagram-as-Code (권장)
- 다이어그램은 **텍스트 기반 도구(Mermaid, PlantUML 등)** 로 작성해 저장소에 소스로 둔다.
  - 버전 관리·diff·리뷰가 가능하고, 코드와 함께 갱신된다.
- 이미지로만 존재하는 다이어그램은 소스(또는 재생성 방법)를 함께 보관한다.

## 2. 표기법 (표준 사용)
- 시스템 구조는 **C4 모델**(Context → Container → Component)을 권장한다.
- 흐름은 **UML 시퀀스 다이어그램**, 데이터는 **ERD**, 상태는 **상태 다이어그램** 등 목적에 맞는 표준 표기를 쓴다.
- 임의 기호를 만들지 말고, 쓰면 **범례(legend)** 로 의미를 명시한다.

## 3. 추상화 레벨
- **한 다이어그램은 하나의 추상화 레벨**만 담는다(전체 컨텍스트와 내부 구현을 한 그림에 섞지 않는다).
- 상세가 필요하면 레벨을 나눠 별도 다이어그램으로 그린다(C4처럼 확대해 들어간다).

## 4. 일관성 · 가독성
- 방향(위→아래 또는 좌→우), 네이밍, 색·모양의 의미를 **일관되게** 유지한다.
- **화살표의 의미**(호출/의존/데이터 흐름)를 명확히 하고, 필요하면 라벨을 단다.
- 요소가 너무 많으면 그룹핑하거나 분할한다. **핵심만** 담고 과도한 상세는 지양한다.

## 5. 유지보수
- 다이어그램은 관련 코드/설계가 바뀌면 **같은 변경에서 갱신**한다. 오래된 다이어그램은 오해를 부르므로 갱신하거나 제거한다.
- 문서 작성 규약은 `documentation-standards.md` 를 따른다.
