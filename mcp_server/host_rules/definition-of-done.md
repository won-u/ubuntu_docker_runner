# Definition of Done (개인 공통 완료 기준)

> 변경이 "완료"로 인정되기 위한 품질 게이트다. 개인 특화 규칙(프로젝트별 명령)은 각 저장소에 둔다.
> **원칙: 게이트를 모두 통과해야 완료다. 통과하지 못한 것을 완료라 하지 않는다.**

모든 변경은 아래 게이트를 **통과한 상태**여야 "완료"로 간주한다. 이것은 **정책**이며,
각 게이트의 **실제 명령**은 프로젝트 저장소의 `CLAUDE.md` / `AGENTS.md` 에 정의한다.

## 필수 게이트 (코드)
- [ ] **포맷**: 프로젝트 표준 포매터를 통과한다.
- [ ] **린트**: 린터에 새 경고가 없다.
- [ ] **타입 체크**: 정적 타입 검사가 통과한다(해당 언어인 경우).
- [ ] **테스트**: 관련 unit/integration 테스트가 모두 green (정직한 판정 — `workflow-rules.md` §2). 신규 로직에는 테스트가 있다.
- [ ] **빌드**: 대상 타깃 빌드가 성공한다 (atomic commit 단위로 독립 빌드 성공).
- [ ] **동작 확인**: 변경한 기능이 실제로 의도대로 동작함을 확인했다.

## 필수 게이트 (품질·안전)
- [ ] **보안**: 비밀이 코드/로그/커밋에 없고, 외부 입력 검증 등 `security-guidelines.md` 기준을 위반하지 않는다.
- [ ] **코드 리뷰**: 리뷰를 통과했다(`code-review-guidelines.md`). blocking 지적이 해소됐다.
- [ ] **커밋 위생**: 커밋이 규약(`commit-guidelines.md`)을 따르고 atomic 하다.
- [ ] **문서**: 공개 API·동작·설정이 바뀌면 관련 문서(README/주석/CLAUDE.md 등)를 갱신했다.
- [ ] **CI**: 파이프라인이 green 이다.

## 보고 (완료 시)
- 어떤 게이트를 어떻게 통과했는지 밝힌다(`workflow-rules.md` §4).
- 게이트를 건너뛰었거나 실패한 것이 있으면 **숨기지 말고 그대로** 보고한다. 실패한 채로 "완료"라고 하지 않는다.

> 프로젝트별 실제 명령·타깃은 각 저장소 `CLAUDE.md`/`AGENTS.md` 의 Build / Test / Validate 섹션 참조.
