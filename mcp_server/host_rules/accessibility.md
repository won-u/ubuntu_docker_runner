# Accessibility (개인 접근성 기준)

> 사용자 인터페이스(주로 웹·앱) 접근성에 일반적으로 통용되는 기준이다. UI를 만들 때 적용한다. 개인 특화 규칙(목표 준수 레벨 등)은 이 문서에 추가한다.
> **원칙: 접근성은 나중에 덧붙이는 기능이 아니라 기본 요건이다. 모두가 쓸 수 있게 만든다.**

## 1. 시맨틱 · 구조
- 의미에 맞는 시맨틱 요소(`button`·`nav`·`main`·`label` 등)를 쓴다 — `div`·`span` 으로 흉내내지 않는다.
- 제목 계층(h1→h6)을 논리적으로 두고, 랜드마크 영역으로 페이지를 구획한다.
- 모든 폼 컨트롤에 연결된 `label` 을 둔다(placeholder 로 대체하지 않는다).

## 2. 키보드 접근
- 모든 상호작용을 **키보드만으로** 수행할 수 있어야 한다(마우스 전용 금지).
- **가시적 포커스 표시를 유지**한다 — `outline` 을 이유 없이 제거하지 않는다.
- 탭 순서를 논리적으로 두고, 모달·메뉴에서는 포커스를 관리한다(트랩 방지·복귀).

## 3. 대비 · 시각
- 텍스트 대비비를 확보한다(WCAG AA SC 1.4.3: 본문 4.5:1, 큰 텍스트 3:1).
- **비텍스트 대비**도 확보한다(WCAG AA SC 1.4.11: **3:1**) — 버튼·입력 테두리 같은 UI 컴포넌트의 경계, 의미를 전달하는 아이콘·차트, 그리고 **포커스 표시**(§2)가 대상이다. 포커스 링이 인접 배경과 3:1 미만이면 "가시적"이라 할 수 없다.
- **색만으로 정보를 전달하지 않는다** — 텍스트·아이콘·패턴을 병행한다(색각 이상 고려).
- 확대(최대 200%)·리플로우에 대응한다. 고정 픽셀 대신 상대 단위를 쓴다.

## 4. 스크린리더 · ARIA
- 이미지에 의미 있는 `alt` 를 주고, 장식 이미지는 빈 `alt` 로 숨긴다.
- **네이티브 시맨틱을 우선**한다 — 필요할 때만 ARIA 를 쓴다("no ARIA > bad ARIA").
- 동적 변경은 live region 으로 알리고, 상태를 속성으로 노출한다(`aria-expanded`·`aria-invalid` 등).

## 5. 모션 · 미디어
- `prefers-reduced-motion` 을 존중해 큰 모션을 줄인다.
- 자동재생·빠른 깜빡임을 피한다(발작 위험).
- 오디오·비디오에 자막·트랜스크립트를 제공한다.

## 6. 검증
- 자동 도구(axe·Lighthouse)로 1차 점검하되, **자동은 일부만 잡는다**는 것을 안다.
- **키보드만으로, 스크린리더로 실제 조작**해 확인한다.
- 접근성도 리뷰·완료 기준의 일부다(→ `code-review-guidelines.md`, `definition-of-done.md`).
