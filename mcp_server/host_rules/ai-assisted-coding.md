# AI-Assisted Coding Hygiene (개인 AI 보조 코딩 위생 기준)

> AI/LLM 도구로 코드를 생성·수정할 때 지키는 기준이다. 개인 특화 규칙(도구·프롬프트 관례 등)은 이 문서에 추가한다.
> **원칙: 생성된 코드도 내 코드다. 검증되지 않은 출력은 신뢰하지 않고, 아는 것과 지어낸 것을 구분한다.**

## 1. 생성 코드는 검증 후 채택
- AI가 만든 코드도 **직접 읽고 이해한 뒤** 채택한다. 이해 못 한 코드를 커밋하지 않는다.
- 반드시 **테스트로 실제 동작을 확인**한다(→ `workflow-rules.md`, `testing-standards.md`). "그럴듯함"은 정확함이 아니다.
- 완료를 주장하기 전에 **실행해 결과를 관찰**한다(→ `definition-of-done.md` 동작 확인).

## 2. 환각(hallucination) 방지
- 존재하지 않는 API·함수·설정·CLI 플래그를 지어내지 않는다. **불확실하면 공식 문서·소스로 확인**한다.
- 의존성은 실재하고 관리되는 것만 추가한다 — **패키지 이름을 지어내지 않는다**(공급망 위험 → `dependency-management.md`).
- 모를 때는 **모른다고 말하고** 확인한다. 추측을 사실처럼 보고하지 않는다(→ `workflow-rules.md`).

## 3. 범위 · 최소 변경
- **요청받은 것만** 구현한다. 요청 밖 리팩터·기능·추상화를 임의로 넣지 않는다(→ `coding-standards/general.md`).
- 넓은 자동 변경(일괄 치환·포맷)은 의도한 범위를 넘지 않도록 확인한다.
- 되돌리기 어려운 동작(커밋·삭제·외부 전송)은 **사용자 확인 후**에만 수행한다(→ `commit-guidelines.md`).

## 4. 비밀 · 프라이버시
- 프롬프트·로그·이슈에 비밀·자격증명·PII 를 붙여넣지 않는다(→ `security-guidelines.md`).
- 외부 서비스로 코드를 보내는 것은 **공개 배포**임을 의식한다. 민감한 코드는 신중히 다룬다.

## 5. 정직한 판정
- 테스트를 동작에 억지로 맞춰 통과시키지 않는다 — 구현이 틀리면 **실패하도록** 둔다(→ `workflow-rules.md`).
- 실패·미완·건너뛴 부분을 숨기지 않고 그대로 보고한다.
- 생성된 커밋 메시지·주석·문서가 실제 변경과 일치하는지 확인한다.
